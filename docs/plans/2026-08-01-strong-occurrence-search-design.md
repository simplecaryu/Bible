# 클릭 기반 Strong 용례 검색 설계

## 목표

Rust/Tauri 데스크톱 앱의 기존 원어 분석 패널에서 단어를 클릭하면 사전 정보와 함께
현재 읽는 권의 동일 Strong 용례를 즉시 보여준다. 사용자가 원할 때 성경 전체 범위로
확장한다. 별도의 원어 입력 검색창은 만들지 않는다.

이 기능은 완전한 오프라인 동작, 키보드 중심 탐색, 계층형 노트와 현재 작업공간을
유지하면서 웹 버전의 유용한 Strong/Englishman's-style 탐색 흐름을 가져오는 것이
목적이다.

## 사용자 흐름

1. 사용자가 읽기 패널의 인터리니어 절을 열고 원어 단어를 선택한다.
2. 분석 패널은 현재와 같이 표제어, 음역, 문맥 뜻, Strong 번호, 형태론과 사전 뜻을
   표시한다.
3. 같은 상세 영역 아래에 현재 권의 동일 Strong 용례를 자동으로 표시한다.
4. 제목은 `창세기 내 용례 3건`처럼 범위를 명시한다.
5. 전체 용례가 더 있으면 `성경 전체 용례 보기 · 총 51건` 버튼을 표시한다.
6. 전체 범위에서는 결과를 정경 순서로 권별 표시하며 50건씩 추가로 가져온다.
7. `현재 형태만 보기` 필터는 선택 사항이다. 기본값은 같은 Strong 번호의 모든
   형태다.
8. 용례를 선택하면 추가 이동 대화상자 없이 현재 활성 성경 패널이 해당 절로
   이동한다. 버튼 포커스와 Enter 키로 같은 동작을 수행할 수 있다.

## 데이터 의미

STEPBible의 확장 Strong 접미사는 사전 상세를 찾을 때 보존한다. 용례 그룹은 고전
Strong 번호의 숫자 부분을 기준으로 묶어 접미사 변형을 함께 찾는다. 따라서
`H7225`와 `H7225G`는 같은 기본 Strong 그룹에 속하지만, 각 결과의 원래 코드는
표시 데이터에 남는다.

용례 결과 하나는 다음 정보를 가진다.

- 권, 장, 절, 토큰 순서
- 원문 표기, 표제어, 음역, 문맥 뜻
- 실제 Strong 코드와 형태론
- 현재 활성 패널에서 켜진 번역들의 절 본문

## Rust 및 SQLite 구조

데이터베이스 빌더는 `original_tokens`에 정규화된 `strong_base`를 저장한다. 다음
복합 인덱스로 권 범위와 전체 범위가 같은 접근 경로를 사용하게 한다.

```sql
CREATE INDEX original_tokens_by_strong_reference
ON original_tokens (strong_base, book_id, chapter, verse, token_index);
```

Tauri 명령 `get_strong_occurrences`는 다음 입력을 받는다.

- `strong`: 선택한 토큰의 Strong 코드
- `book_id`: 현재 권 범위이면 권 ID, 성경 전체이면 없음
- `morphology`: 형태 필터를 켰을 때만 전달
- `translation_ids`: 활성 패널에 표시 중인 번역
- `offset`, `limit`: 페이지 위치와 크기

응답에는 정규화 Strong 코드, 현재 조건의 전체 개수, 다음 페이지 존재 여부와 최대
50개의 결과가 포함된다. Rust는 참조별 번역 본문을 같은 읽기 전용 SQLite에서
결합해 반환한다. 프런트엔드가 장별 데이터를 다시 여러 번 요청하지 않게 한다.

## 프런트엔드 구조

분석 패널의 기존 `analysis-token-detail` 스크롤 영역 안에 다음을 순서대로 렌더링한다.

1. 기존 사전 상세
2. 범위 및 형태 필터 컨트롤
3. 용례 결과 목록
4. 성경 전체 확장 또는 다음 50건 로드 버튼

별도 dialog나 새 작업공간 패널은 만들지 않는다. 토큰을 빠르게 연속 선택할 때 이전
요청 결과가 새 단어에 붙지 않도록 기존 request key 검사를 용례 요청에도 적용한다.

## 오류 및 경계 조건

- Strong 코드가 없는 토큰에는 용례 UI를 표시하지 않는다.
- 현재 권에 결과가 없더라도 전체 개수와 전체 검색 버튼은 표시한다.
- 잘못된 권, 번역, offset과 과도한 limit은 Rust 명령 경계에서 거부한다.
- 결과 로딩 실패는 사전 상세를 지우지 않고 용례 영역에 재시도 가능한 오류로
  표시한다.
- 전체 결과는 한 번에 반환하거나 렌더링하지 않는다.

## 테스트

- DB 빌더: `strong_base` 정규화와 복합 인덱스 생성
- Rust corpus: 권 범위, 전체 범위, 정경 순서, 형태 필터, 페이지 경계, 번역 본문 결합
- Tauri 명령: 입력 검증과 직렬화
- 프런트엔드 모듈: 범위 레이블, 확장 버튼, 누적 페이지, stale response 처리
- 앱 연결: 단어 선택 시 현재 권 자동 조회, 전체 확장, 결과 선택 시 활성 패널 이동
- 기존 원어·노트·작업공간 테스트 전체 회귀

## 배포

구현은 `simplecaryu/Bible`의 `desktop-rust` 브랜치에 push한다. 전체 검증과 AppImage
빌드 후 다른 Linux 컴퓨터에서 저장소를 다시 구성하지 않고 실행할 수 있도록 fork의
GitHub prerelease에 AppImage를 첨부한다. 데이터 출처와 라이선스 문서는 AppImage에
계속 포함한다.

## 이번 범위에서 제외

- 원어 문자열을 직접 입력하는 검색창
- TSK 관주 이식
- Open Scriptures의 별도 Strong 사전 데이터 이식
- 웹 버전의 대화상자와 스타일을 그대로 복사하는 작업

이 항목들은 클릭 기반 용례 검색이 안정화된 뒤 별도 단계로 평가한다.

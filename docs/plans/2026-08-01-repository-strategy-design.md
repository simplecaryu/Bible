# Rust 데스크톱 전환 저장소 운영 설계

## 배경

현재 `origin/main`은 브라우저 기반 성경 앱을 나타낸다. 로컬 작업은 이 계보 위에
Tauri/Rust 백엔드, 오프라인 데이터베이스, 원어 연구 도구, 계층형 노트와 Linux
AppImage 배포를 추가했다. 변경 범위가 크지만, 아직 다른 사용자의 검토를 받지 않아
데스크톱 앱이 기존 웹 앱을 완전히 대체할지는 결정되지 않았다.

## 결정

현 단계에서는 GitHub fork나 별도 저장소를 만들지 않는다. 현재 작업을
`desktop-rust` 브랜치로 게시하고 `main`을 대상으로 하는 Draft PR을 만든다.

- `main`은 검토 기간 동안 기존 웹 앱의 안정된 기준선으로 유지한다.
- `desktop-rust`는 현재 Tauri/Rust 전환 작업의 검토 및 후속 수정 브랜치다.
- Draft PR은 병합 약속이 아니라 변경 내용, 실행 방법과 피드백을 모으는 공간이다.
- 생성된 파일과 로컬 작업 지침인 `src-tauri/gen/`, `AGENTS.md`는 PR에 포함하지 않는다.

## 검토 후 결정

피드백을 받은 뒤 다음 중 하나를 선택한다.

1. 데스크톱 앱이 기존 제품을 대체하면 Draft PR을 정리해 `main`에 병합한다.
2. 웹 앱과 데스크톱 앱이 독립적으로 배포·버전 관리되어야 하면 데스크톱 앱을 별도
   저장소로 분리한다. 이 경우 fork보다 독립 저장소를 사용하되 Git 이력과 저작권·출처
   기록은 보존한다.
3. 데스크톱 전환을 중단하면 `main`은 변경 없이 유지하고 실험 브랜치를 보관하거나
   종료한다.

`desktop-rust`를 영구적인 두 번째 제품 브랜치로 운영하지 않는다. 장기간 서로 다른
릴리스와 이슈를 관리해야 하는 시점이 별도 저장소로 분리할 기준이다.

## 게시 및 검증 절차

1. 현재 작업을 `desktop-rust` 브랜치에 고정한다.
2. Rust 포맷, 테스트, 린트와 프런트엔드 테스트·구문 검사를 실행한다.
3. 브랜치를 원격에 게시한다.
4. `main` 대상 Draft PR을 만들고 큰 전환 작업임을 제목과 본문에 명시한다.
5. 로컬 `main` 브랜치 포인터를 `origin/main`에 맞추되 작업은 `desktop-rust`에서
   계속한다.

게시 직전 fetch에서 `origin/main`이 분기점 이후 36개 커밋 전진한 것이 확인됐다.
해당 변경에도 원어 검색과 인터리니어 기능이 포함되어 있으므로, Draft PR 단계에서는
두 구현을 즉시 merge/rebase하지 않는다. 먼저 기능과 데이터 모델을 비교한 뒤 통합
방식을 별도로 결정한다.

## 안전성

브랜치 게시와 PR 생성 전에 기존 15개 커밋은 어떤 방식으로도 재작성하지 않는다.
로컬 `main`을 맞추는 작업은 `desktop-rust`가 원격에 게시된 후에만 수행한다. 미추적
파일은 스테이징하지 않으며 PR 변경 목록을 생성 직전에 다시 확인한다.
